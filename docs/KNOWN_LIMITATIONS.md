# Known Limitations

- The Apple Silicon build and the complete 1,690-test CTest inventory pass. It has 1,683 enabled passes, 3 expected platform-condition skips, and 7 registered disabled tests. An earlier sequential run had isolated native crashes in three inherited FreeCAD tests. Each exact test then passed alone, passed 10 consecutive stress runs, and passed in the clean complete run.
- The local build script previously failed on macOS because it required `nproc`; a fix now has a self-test.
- The local CMake path can select the installed SDK version as the deployment target.
- The connected first-launch flow creates a new design or opens an existing file without asking the user to select a workbench or modeling engine. The broader inherited FreeCAD menus and workbench selector still remain visible outside this guided flow.
- First launch completes only after it has a saved local document, matching persistent project, visible assistant workspace, and editable prompt. Native tests cover keyboard activation, Tab and Shift-Tab order, and 4.5:1 light and dark choice contrast. A complete manual VoiceOver review is still required before production release.
- Native and scripted provider mutations use the acceptance coordinator. Verified restore and interrupted-restore recovery work. Recovery runs on saved-document restore and before the next provider turn.
- Human candidate review keeps the canonical CAD file, accepted head, project metadata, and accepted project state unchanged until acceptance. The deterministic FreeCAD GUI assertions, fault-injection tests, save-close-reopen-restore-recompute-compare tests, the complete VibeCAD Python regression, representative native tests, and the clean complete 1,690-test CTest inventory provide acceptance evidence. The GUI test runner still has the separate code-134 shutdown limitation listed below.
- Revision timeline, comparison, restore, report, and branch controls exist. A branch copies the exact accepted FCStd file, a content-bound lineage record, the accepted design state, and the current conversation history into a new local project identity. It does not create a collaboration-server branch because no hosted collaboration service is included.
- A provider must call the design-brief update tool during each CAD mutation. A missed update rejects the full turn safely; one automatic provider retry is not implemented yet.
- A deterministic provider transactional baseline passes 3 of 3 series trials for exact box, selected-face hole, selected-feature fillet, and hollow enclosure workflows. It uses the complete provider tool, acceptance, revision, save, reopen, and recompute path, but it is not a live-model conversational score.
- Typed provider export supports STL, 3MF, OBJ, STEP, IGES, and exact-page TechDraw PDF, DXF, and SVG. Real checks reopen all 3D formats and parse drawing signatures. One typed manufacturing-drawing workflow passes accepted-revision save, close, reopen, semantic validation, compare, export, and restore. Automatic standard-view layout, section views, detail views, geometric tolerances, and editable title-block fields are not yet complete.
- Typed native assembly tools create containers, insert links, ground components, create joints, solve, extract BOM data, analyze exact solid interference, replace topology-compatible sources, and create and restore native exploded views. One fixed jointed assembly and one exploded-view workflow pass accepted-revision semantic validation, reopen, compare, and restore. An assembly can have only one VibeCAD-managed exploded-view configuration. Its moves are translation-only. Motion-range checks, nested-assembly BOM flattening, and collaborative assembly locking are not complete.
- Content-bound STEP import accepts a human-registered `.step` or `.stp` asset of at most 512 MiB. The assistant panel has an accessible STEP file-selection control. Registration and asset hashing run outside the GUI thread. Validation requires valid solid geometry, positive volume, and nonempty X, Y, and Z bounds. It rejects surface-only content. The importer does not preserve a STEP assembly hierarchy. It creates one static native `Part::Feature` and does not reconstruct source sketches or feature history. Native downstream features can remain linked and editable. Validation uses a separate safe-mode `FreeCADCmd` process with file, environment, time, memory, and output bounds. On macOS, a Seatbelt profile also denies network access, denies child execution, denies writes outside staging, and limits reads to required runtime roots. Detached BREP parsing occurs outside document-thread dispatch. Native shape copy, assignment, recompute, and final identity checks still run on the document thread. A hard parent-process stop can leave a validator temporary directory because no safe startup sweep exists. `/usr/bin/sandbox-exec` is deprecated; if Apple removes it, STEP validation fails closed until a replacement exists. Linux STEP validation fails closed because it does not yet have an equivalent OS sandbox. The secure asset store requires POSIX descriptor-relative file operations. STEP attachment fails closed on Windows until a Win32 handle-relative implementation exists; other provider turns remain available.
- Direct named spreadsheet parameters can drive existing numeric CAD properties. One three-dimension size-variant workflow passes acceptance, semantic reopen validation, STEP/STL export, compare, and restore. The typed binder does not create compound arithmetic expressions, lookup tables, configuration matrices, or automatic variant families.
- Native material cards persist through accepted-revision reopen and restore, and assembly BOM output reads their material names. One Aluminum-6061-T6 workflow passes. Material substitution rules, lifecycle assessment, supplier data, stock forms, finish specifications, and organization-approved material catalogs are not complete.
- Native mesh analysis, justified defect repair, shape-to-mesh conversion, mesh-to-solid recovery, accepted reopen, STL/3MF/OBJ export, compare, and restore pass for supported watertight meshes. The acceptance boundary rejects open surface meshes. Automatic decimation, remeshing, smooth-surface reconstruction, scan cleanup, and repair of severe self-intersection are not complete.
- One native closed-boundary surface fill and thickening workflow passes accepted reopen, STEP/STL export, compare, and restore. Surface blend, extension, multi-section loft, continuity-class control, complex trim networks, and advanced NURBS editing do not yet have the same accepted-workflow evidence.
- Native CAM workflows pass facing and one ordered profile, pocket, and peck-drilling sequence. They preserve explicit stock, two tools, native paths, protected-model collision checks, accepted reopen, controlled GRBL output, compare, and restore. The typed postprocessor supports generic GRBL and LinuxCNC output only. It does not apply a named machine definition, machine travel limits, fixtures, work offsets, holder collision, optimized feeds and speeds, probing, multi-axis motion, or controller-specific certification.
- One native static FEM cantilever workflow passes typed analysis setup, material, exact support and load references, asynchronous Gmsh volume meshing, asynchronous CalculiX solve, finite result validation, accepted reopen, compare, and restore. Frequency, thermal, buckling, nonlinear, contact, convergence refinement, and certified engineering checks do not yet have the same accepted-workflow evidence. The broad upstream `TestFemApp` aggregate includes legacy golden writer comparisons that fail against current generated input and several slow unrelated geometry fixtures; focused result, Gmsh, material, and real acceptance tests pass.
